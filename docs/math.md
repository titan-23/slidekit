# 数式の書き方

数式は文章の断片 `Math(r"...")` か `slide.equation(expression=r"...")` で指定する。
記法は LaTeX に似た slidekit の記法で、式は PowerPoint の編集可能な数式（Office Math）として書き出す。
受け付けない記法はエラーにし、誤記を見逃さない。

```python
from slidekit import Math, Rect, Text

slide.text(id="cost", area=Rect(60, 120, 600, 40), text=[Text("計算量は "), Math(r"O(n \log n)"), Text(" である。")])
slide.equation(id="sum", area=Rect(60, 180, 600, 60), expression=r"\sum_{i=1}^{n} i = \frac{n(n+1)}{2}", align="center")
```

## 書き方の基本

- 式を `$` で囲まない。式の中に改行も書かない。
- 波括弧 `{…}` は見えないまとまりである。添字や引数を 2 文字以上にするときに使う。
- 添字は `x_i`・`x^2`・`x_{ij}^{n+1}` と書く。波括弧のない添字は次の 1 文字になる（`x_12` は x₁ の後に 2）。
- プライム `f'`・`f''` は上付きになる。Unicode の添字 `x₂`・`x²` も使うことができる。
- `/` は横書きの分数（`a/b`、`(a+b)/2`）、`\frac{a}{b}` は上下に置く分数である。記号の斜線は `\slash` か `\text{/}` で書く。
- `-` と `*` はそれぞれ負号 − と ∗ になる。
- 英字と小文字のギリシャ文字は斜体、大文字のギリシャ文字・数字・記号・関数名は立体になる。大文字のギリシャ文字を斜体にするときは `\varGamma` などを使う。要素が太字なら、すべて太字になる。
- `log`・`sin`・`max` などの関数名は `\` の有無にかかわらず立体の関数名になる。資料に固有の関数名は `deck.toml` の `[math]` に `functions = ["rank"]` のように加える。
- `\` のない語は、関数名と `sqrt`（`sqrt(x)` は根号）を除いて、斜体の文字の並びになる。`frac` や `sum` は命令にならない。
- 大型演算子（`\sum`・`\int` など）の後には引数が要る。引数は次のまとまりから、同じ段の次の二項演算・関係・句読点の前まで（なければ波括弧や括弧の終わりまで）である。`\int_0^1 f(x)\,dx` の引数は `f(x)\,dx`、`\sum_i a_i + b` の引数は `a_i` になる。
- 大型演算子と関数名の添字は記号の右に置き、`\limits` を付けると上下に置く。ただし、文中の数式では大型演算子の `\limits` は適用されず、添字は右に付く（PowerPoint の動作。`\max\limits_i` などの関数名は文中でも下に付く）。
- `:` は句読点として扱い、後ろだけが空く（`;` と同じ。PowerPoint の表示に合わせた）。`\bmod` は前後に `\:` の空白を置いた立体の mod になる。

## 括弧

- 普通の括弧 `(`・`[`・`\{`・`\langle`・`\lceil`・`\lfloor` は通常の文字で、中身の高さに合わせて伸びない。
- 伸ばしたい箇所は `\left(`・`\right)` で囲む。`\left.` と `\right.` は見えない括弧である。
- `\middle|` は `\left` と `\right` の間に伸びる区切りを置く。1 組の括弧の中では 1 種類の記号だけを使うことができる。
- `(`・`[` は `)`・`]` のどちらでも閉じることができる。区間 `[0, n)`・`(0, n]` をそのまま書くことができる。ほかの括弧は対応する閉じ括弧が要る。
- 縦線 `|`・`\|` は組にしない。`|x|^2` の上付きは閉じる側の縦線に付く。条件を表す縦線には、前後に空きが入る `\mid` を使う。

## 文章

- `\text{…}` の中は文章として、要素の文字の書体（日本語は `font_japanese`、欧文は `font_latin`）で書き出す。中身は置き換えない（`-` も負号にならない）。
- `\text{…}` の中の `“`・`”`・`‘`・`’`・`×`・`○` などの記号（PowerPoint が既定で和文の書体で描く記号。文字の計測と同じ一覧）は、欧文だけの文章の中でも `font_japanese` で描かれる。計測にも同じ書体を使う。
- 日本語は `\text{…}` の中に書く。外に書くとエラーになる。
- `\text` の中には波括弧と命令を書くことができない。

## 独立した数式と文中の数式

- `equation()` で、空でない断片が数式 1 つだけの要素は、独立した数式（LaTeX の別行立ての数式。Office Math の `m:oMathPara` と `m:jc`）として書き出し、`align` の揃えを数式の段落に書く。
- それ以外の数式（`text()`・`box()`・表のセル・ページ題名、文章と並べた `equation()`）は、文中の数式である。段落の揃えのとおりに置く。
  明示改行（`\n`）で分けた行のうち、数式があり通常の文字のない行には、その行の後に幅 0 の空白（U+200B）だけの文字を加えて文中の数式にする（改行のない段落では段落の末尾）。
  加えないと、PowerPoint はその行を独立した数式として扱い、段落の揃えによらず枠の中央に置く（PowerPoint 16.0 の build 20430 で確かめた）。
- 独立した数式では最上位の分数の分子と分母を縮めず、大型演算子（`\sum`・`\int` など）を大きな字形にする。文中の数式では分数の分子と分母を 73 % に縮める。
- 中央揃えの独立した数式では、PowerPoint は式の後ろに「段落の末尾の書式の欧文書体の空白の送り幅 × 数式の文字サイズ」の幅を加えてから中央に置く。この幅は末尾の書式の文字サイズによらず、書体は段落の末尾の書式・文字枠の書式・テーマの本文の欧文書体の順に決まる。slidekit は段落の末尾の書式に要素の `font_latin` を書き、同じ幅を段落の左の余白にして、式の中心を枠の中心にそろえる。幅は計測のフォントから求める（PowerPoint 16.0 の build 20430 で確かめた。左揃えと右揃えではずれない）。
  末尾が添字の式では、PowerPoint は添字の後の空き（MATH 表の SpaceAfterScript × 文字サイズ）と末尾の添字の斜体補正も式の箱に含めるので、slidekit はその和も左の余白に加える。20・28・36 pt の式で、中心の差は 0.17 pt 以内だった。
- 文中の数式は、行の残りに入らないときも式の途中で改行しない（改行しない箱 `m:box` の `m:noBreak` で包む）。式ごと次の行へ送り、枠より長い式は右へはみ出す（配置の検査では `text_overflow`）。包まないと、PowerPoint は式の途中の演算子の後で改行する。
- `equation()` は既定で枠の幅で折り返さない（同梱のテーマの `[defaults.equation] word_wrap = false`）。折り返しを有効にすると、PowerPoint は枠より長い独立した数式を演算子の前で改行し、計測と合わなくなる。資料のテーマで `word_wrap = true` にすれば折り返す。
- 0.1 までの版では、数式だけの段落と、明示改行で分けた数式だけの行は、揃えの指定によらず中央に置かれた。中央に置かれる前提で枠をずらしていた資料は、枠の左端を式の左端に合わせる。式の後に空白を置いて左揃えにしていた資料は、空白を消してよい（残しても表示は変わらない）。

## 寸法の計算

数式の寸法（送り幅、上下、描画範囲）は、数式の書体（既定は Cambria Math）の OpenType の MATH 表で式を組んで計算する（`slidekit.math.metrics`）。書体には MATH 表が要り、ない書体はエラーになる。`context.measure_math(式, 大きさ)` と `slide.measure()` も同じ計算を使う。

組み方は MathML Core の配置の規則と MATH 表の仕様に従う。Office Math と違う点は PowerPoint で変換した PDF の字形の位置と照合して合わせた（`metrics.OFFICE` の値）。照合には PowerPoint 16.0.20430.20146（2026-10-12）を使った。添字の土台、関数名の後の `\{`、数字の間のカンマ、`\bot`、関数の適用の後、横書きの分数、関数名を土台にした上下に置くものの規則は、16.0.20430.20182（2026-10-20）で照合した。主な規則は次のとおりである。

- 文字の大きさの段は添字・上下の添え字・文中の数式の分数の分子と分母で 1 段、根号の次数で 2 段進む。1 段目は MATH 表の ScriptPercentScaleDown（Cambria Math では 73 %）、2 段目以降は ScriptScriptPercentScaleDown（60 %）を掛け、添字用の字形（GSUB の ssty）を使う。
- 原子の間の空きは TeX と同じ規則で、単位は 1/18 em（細 3、中 4、太 5）である。添字の中では二項演算・関係の前後などの空きを入れない。原子の種類は命令の一覧の「種類」の列の値である（`:` は句読点、`\ldots`・`\cdots` は内部、`\bot` は関係、ピリオドとカンマは句読点）。数字の間のカンマとピリオド（`1,2`）は数の一部で、後ろを空けない。ただし、間に空白がある場合（`1,\,2`）と、数学用の英数字になる数字（要素の太字、`\mathbf`・`\mathbb`・`\mathsf`・`\mathtt` など）の間では、句読点として後ろを空ける（PowerPoint は要素の太字の数字を数として扱わなかった）。
- 斜体の文字の後に立体の文字（演算子・括弧など）か空白が続くとき、および文中の数式の末尾が斜体の文字のとき、その文字の斜体補正を加える。末尾の斜体補正は添字・記号付き・上線・根号の末尾の文字からも伝わる。空白の命令の幅は一覧の値のまま（`\,` は 1/6 em）で、PowerPoint の PDF の空白の幅との差は 0.006 em 以内だった。
- 添字は MathKern で詰める（土台と添字の値の和を 2 つの高さで求め、詰める量の小さい方を使う）。下付きは土台の送り幅の後に置く。
- 添字の上下の位置と MathKern は、土台の並びの最後の原子で決める。`(\frac{a}{b})^2` の上付きは、括弧の中の高さによらず、閉じ括弧に付けたときと同じ通常の位置になる（PowerPoint と同じ）。土台が分数や伸びる括弧だけのとき（`{\frac{a}{b}}^2`・`\left(\frac{a}{b}\right)^2`）は、MATH 表の規則でその高さに合わせて上げる。
- 関数名と引数の間に 3/18 em を空ける。引数が `(`・`[`・`\{` で始まるときは空けない。
- 大型演算子の添字の後には MATH 表の SpaceAfterScript を入れず、添字の末尾の斜体補正だけを加える。独立した数式で添字を右に置く大型演算子は引数との間を空けず、上下に積むときは 3/18 em を空ける。文中の数式の積分以外の大型演算子は、添字を文字の添字と同じ高さに置く。
- 独立した数式の大型演算子は、MATH 表の DelimitedSubFormulaMinHeight 以上の最初の字形にする（Office は DisplayOperatorMinHeight とこの定数を逆に読み、Cambria Math の値はそれに合わせてある）。
- 伸びる括弧（`\left`・`\right`・`\binom`）は、中身の数式の軸からの上下の大きい方の 2 倍に 0.901 を掛けた長さ以上の最初の字形にする（TeX の `\delimiterfactor` と同じ）。
- 根号の字形が必要な長さより長いときは、余りの半分を中身の上の空きに加える。横書きの分数の斜線は分数の斜線（U+2044）の字形で計測する。
- 関数の適用（引数のある関数名。`\log x`・`\max(a,b)`）の右側は内部（inner）として扱う。後に普通の文字・句読点・開き括弧が続くと、空白の命令を挟んでも 3/18 em を空ける（`\log x,y`・`\log x\,y`・`\log x(y)`・`\max(a,b)\,c`）。二項演算・関係・閉じ括弧の前と、添字の中では空けない（`\log x+y`・`(\log x),y`）。根号は、中身の最後が関数の適用のときだけ同じにする（`\sqrt{x\log x},y` は空け、`\sqrt{x},y` は空けない）。
- 横書きの分数（`a/b`）も内部として扱う。前に普通の文字か閉じ括弧が、後に普通の文字・句読点・開き括弧が続くと 3/18 em を空け（`x a/b`・`2a/b`・`a/b,x`）、二項演算・関係との間と、括弧の中と添字の中では空けない（`x+a/b`・`x(a/b)`・`x^{1/4}`）。前の斜体の文字と、分数の末尾の斜体の文字の斜体補正も加える。
- 上下に置くもののうち、土台が引数のない関数名だけのもの（`\underset{i}{\max}`）は、通常の文字と同じ種類にして前後を空けない（PowerPoint は `m:limLow` の土台の関数名を関数として扱わない）。`\max\limits_i x_i` と `\underset{x \in S}{\arg\min} f(x)` は関数名のままである。
- `\text{…}` の中身は要素の文字の書体（`font_japanese`・`font_latin`）で、文字の計測と同じ規則で計測する。後ろの空白も幅に含め、描画範囲は最初と最後の字形の範囲にする。PowerPoint は `\text` の文字を添字の中でも自動では縮めないので、slidekit は添字などの中では縮めた大きさ（1 段目は 73 %、2 段目以降は 60 % を掛け、1/100 pt に丸める）を書き出し、計測にも同じ大きさを使う。この倍率は Cambria Math の値で、数式の書体を替えても変えない（ほかの書体では、添字の数式の文字と `\text` の文字の大きさが少し違うことがある）。独立した数式で添字などの外にある分数は、入れ子でも中身の `\text` を縮めない（PowerPoint は独立した数式の入れ子の分数を縮めない。「残る差」を参照）。

### 照合データと誤差

`tests/data/powerpoint_math.json` は PowerPoint（16.0.20430.20182、2026-10-20）で変換した PDF から計測した照合データである。照合データを作る道具（`tests/tools/powerpoint_math_data.py`）の式の一覧の先頭の 140 式を 20 pt の文中の数式と独立した数式で置き（280 件）、文中の数式は送り幅と描画範囲、独立した数式は描画範囲の幅と高さを持つ。描画範囲は、PDF を pypdfium2 で 1 pt あたり 8 画素の画像にして求める。数式の書体は Cambria Math（`cambria.ttc` の 1、Version 6.99）、文字の書体は Yu Gothic UI と Arial である。

試験 `test_math_metrics_match_powerpoint` は計測と照合データの差（計測 − PowerPoint）を次の基準で確かめる。数式の書体のハッシュ値が照合データと違う環境では省略する。

| 項目 | 基準 | 今の値 |
|---|---|---|
| 幅の差（文中は送り幅、独立は描画の幅）が 0.05 em 以内の式の割合 | 9 割以上 | 280 件中 279 件（99.6 %。中央値 0.0043 em、90 % 点 0.0151 em） |
| 幅の差の最大 | 0.12 em 以内 | 0.0554 em（独立の `\log x\frac{a}{b}`） |
| 描画の上下の差（文中は基線より上と下、独立は高さ）の最大 | 0.1 em 以内 | 0.0485 em（文中の `a/b`） |

照合データの項目に `excluded`（比べない理由の文字列）があれば、その項目は比べない。道具で作った照合データには `excluded` を付けない（今の照合データにもない）。試験は比べない項目と道具の式の一覧との対応を照合データから求めるので、作り直しても直さなくてよい（この節の件数と「今の値」は直す）。

照合データは PowerPoint を使って次のように作り直す。PowerPoint を使う処理は一度に 1 つだけ実行する。

```bash
python tests/tools/powerpoint_math_data.py --output 新しい照合データ.json --work 作業ディレクトリ
python -m slidekit.math.metrics 新しい照合データ.json --font C:/Windows/Fonts/cambria.ttc:1 \
    --latin C:/Windows/Fonts/arial.ttf --japanese C:/Windows/Fonts/YuGothM.ttc:1
```

2 つ目のコマンドは照合データと計測を比べて、合格なら 0、不合格なら 1、照合できなければ 2 を返す（`--json` で式ごとの差）。WSL ではフォントのパスを `/mnt/c/Windows/Fonts/…` にする。PowerPoint・数式の書体の版を変えたときと、数式の組み方か書き出しを変えたときに作り直し、差を確かめてから入れ替える。実機の PowerPoint で計測を確かめる試験は `tests/test_powerpoint_math.py`（`SLIDEKIT_TEST_POWERPOINT=1` のときだけ実行）である。

### 残る差

照合データにない次の式では、PowerPoint で計測した差（計測 − PowerPoint。2026-10-20 の確認）が基準を超える。

- 伸びる括弧の中身が高いか上下に偏る式。PowerPoint は括弧を数式の軸の上下に等しく置かないことがあり、大型演算子の添字を括弧の長さに含めないことがある。`\left(\frac{\frac{a}{b}}{c}\right)` は独立した数式で描画の幅 −0.146 em・高さ +0.390 em、文中の数式で送り幅 −0.102 em・基線より下 +0.203 em、`\left(\sqrt{\frac{a}{b}}\right)` は文中の数式で基線より下 +0.204 em、`\left(\sum_{i=1}^{n} a_i\right)` は文中の数式で送り幅 +0.068 em・基線より上 +0.114 em だった。
- 独立した数式の中の入れ子の分数。PowerPoint は入れ子の分数の分子と分母も縮めない（20 pt の式で 20.04 pt）が、計測は 1 段縮める。書き出しは中身の `\text` も縮めない（周りの数式の文字と同じ大きさにする）が、計測はほかの文字と同じく 1 段縮めるので、幅と高さが小さく出る。

次の差は基準の中だが、資料の行の幅や位置に現れることがある（2026-10-20 の確認）。

- 添字・分数の中の関数名と引数の間の空き。PowerPoint は約 0.21〜0.22 em（段の文字サイズの em）を空け、計測は 3/18 em にする。`\frac{a}{\log x},y` は文中の数式で −0.069 em、`x^{\log n},y` は独立した数式で −0.054 em だった。
- 添字の中の `;`（`r_{A;C}`）。計測は PowerPoint より約 1.1 pt 広い（生成した資料の 24 pt の式。原因は確かめていない）。
- 上付きと下付きの両方がある式（`x_i^2`・`x_{i,j}^2`）の描画の下端は、計測が PowerPoint より 0.61〜0.66 pt 深い（校正用の資料の 20 pt の式）。
- 独立した数式の根号の描画は、PowerPoint では基線に対して計測より低い（24 pt で約 1.3 pt、18 pt で約 0.7 pt）。
- 上付きの中に横書きの分数がある式（`m^{1/4}`・`2^{\lceil a/2\rceil}`）では、PowerPoint は上付きを計測より約 0.6 pt 高く置く（20 pt。式の寸法は 0.035 em 以内で合い、その行は予測より約 1.3 pt 下に置かれる。原因は確かめていない）。

照合データの幅の差の最大（独立の `\log x\frac{a}{b}` の −0.0554 em、文中は −0.0436 em）は、関数の適用とその後の分数の間の空きによる。PowerPoint は計測より約 0.04〜0.06 em 広く空ける（原因は確かめていない）。次に大きい文中の `a_1 + \cdots + a_n` の +0.0496 em は、`\cdots` とその後の二項演算の間の空きによる。PowerPoint は約 3/18 em、計測は 4/18 em にする（PDF の字形の位置で確かめた）。

計算した寸法は PowerPoint の表示と完全には一致しない。最終 PPTX の表示を確認する。

## エラーの文言

受け付けない記法は理由・該当する字句・元の式での位置を示すエラーになる。未対応の命令には近い命令か対応していない理由を添える。

```text
未対応の数式命令: \alpah（3 文字目）。近い命令: \alpha、\aleph、\nabla
閉じ括弧がない: {（6 文字目）
日本語は \text{...} の中に書く: の（3 文字目）
```

## 対応していない記法

次の記法は「未対応の数式命令」のエラーになる。

- 環境 `\begin{…}`（`cases`・`pmatrix`・`aligned` など）。行と列の間隔を PowerPoint で校正する必要があり、式の中の改行を受け付けない記法で行の区切りをどう扱うかも決まっていないためである。
- 括弧の大きさの指定（`\big` など）。Office Math では括弧の大きさを指定できない。伸ばす括弧は `\left`・`\right` で書く。
- `\displaystyle`・`\textstyle`、`\color`・`\textcolor`、`\hspace`・`\mkern`、`\over`・`\choose`、`\overrightarrow`、`\overbrace`・`\underbrace`、`\substack`、`\tag`。

負の空白 `\!` は受け付けるが、何も出力しない。
